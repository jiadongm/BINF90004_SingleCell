Part 2 Single cell RNA-seq

Simplified central dogma: DNA → RNA → protein

  • DNA is (nearly) the same in every cell

    • scDNA-seq is niche, e.g. evolution of cancer clones

  • scProt-seq is hard to scale: can measure many cells, or many proteins, but not both

  • RNA is more transient, but reflects cell activity well

How it works

  1. Dissociate the tissue into single cells
  2. Capture each cell in a droplet with a barcoded bead
  3. Every transcript from that cell gets the same barcode
  4. Sequence everything; sort by barcode

Output: a genes × cells matrix of counts.

Cells or nuclei?

scRNA-seq

  • whole cells
  • needs tissue that dissociates gently
  • cytoplasmic RNA included

snRNA-seq

  • nuclei only
  • works on frozen / tough tissue
  • cytoplasm discarded

Does cytoplasmic RNA matter?

Yes. Eg ‘Single-Nucleus RNA-Seq Is Not Suitable for Detection of Microglial Activation Genes in Humans’ (Thrupp et al., 2020; Cell Reports)

Quality control

Not every droplet (unique barcode) is a good cell:

  • Empty droplets — ambient RNA only; low counts, low gene number
  • Dying cells — membrane compromised, cytoplasmic RNA leaks out, mitochondrial fraction rises
  • Doublets — two cells, one barcode (hardest to detect)

Normalisation

Cells differ in total counts for reasons that are both biological and technical: capture efficiency, sequencing depth (budget), cell size, transcriptional activity.

  • Naive log-normalisation: divide raw counts by lib size, scale, log. Simple & fast.
  • scran: pool cells (clustering) first to estimate cluster-wise lib size (more robust).
  • SCTransform: negative binomial regression: regress lib size our.

These methods don’t stricly seperate bio vs tech variations in lib size. You need spike-ins (synthetic negative control RNAs).

Naive log-normalisation toy example

counts <- cbind(A = c(10, 5, 1), B = c(20, 10, 2), C = c(2, 10, 20))
rownames(counts) <- c("ACTB", "GAPDH", "MYH7")
rbind(counts, libsize = colSums(counts))
         A  B  C
ACTB    10 20  2
GAPDH    5 10 10
MYH7     1  2 20
libsize 16 32 32
round(log1p(t(t(counts) / colSums(counts)) * 1e4), 2)
         A    B    C
ACTB  8.74 8.74 6.44
GAPDH 8.05 8.05 8.05
MYH7  6.44 6.44 8.74

Toy numbers are chosen so the arithmetic is doable in the room: the CP10K values are exactly 6250 / 3125 / 625.

B is A sequenced twice as deep - same cell, more reads. C has the SAME library size as B, so depth cannot explain it; it is a different cell.

Ask before revealing the second chunk: which two of these three cells are the same? Most will say A and B look different, because the raw counts differ by 2x everywhere. That is exactly the mistake normalisation exists to prevent.

Then push once: normalisation made A and B identical - but it CANNOT tell you whether B really was a deeper-sequenced A, or a cell with genuinely twice the RNA. Same numbers either way. That is the identifiability point from the previous slide, now visible.

A and B are now identical — B was A, sequenced twice as deep.

C shares B’s library size, so depth explains nothing: a different cell.

Feature selection

~19,000 genes. Most are uninformative:

  • not expressed
  • expressed everywhere at the same level (housekeeping)


Keep the 2,000–5,000 most variable genes.

Caveat: a gene you filter out cannot be discovered.

Dimension reduction: PCA

Still thousands of dimensions, and they are correlated.

PCA finds linear combinations capturing the most variance.

  • Use the first 10–50 PCs for everything downstream
  • Faster, and drops noise in the tail components
  • Not good for visualisation — 2 PCs is not enough

Visualisation: UMAP and t-SNE

Non-linear projections to 2D. Good at preserving local structure — cells that were neighbours stay neighbours.

UMAP: what it does not mean

  • Distance between clusters is not meaningful
  • Cluster area is not population size
  • Apparent gaps can be artefacts of the parameters
  • Clusters can appear that are not there


It is a picture for looking at, not a measurement. Never test a hypothesis on UMAP coordinates.

Batch effects

Cells cluster by donor instead of by cell type. Each sample carries its own technical signature.

Integration

MNN · CCA · Harmony — all find a shared space where donors overlap.

There is no measurement that tells you it worked.

“The donors mix better” is also exactly what over-correction looks like — and over-correction deletes real biology.

Here the donors differ by developmental stage. Some separation between them is the signal we came to study. We integrate by donor, not by stage — deliberately.

It also did something our practical does not

You have just seen that integration can remove real biology along with the batch effect. Here is how the agent checked whether it had:

“Clustering on unintegrated PCA gave clusters that were stage-exclusive and donor-exclusive — 7 clusters were ≥90% a single donor. That can’t distinguish development from batch. After Harmony: 0 donor-dominated clusters, while 10 clusters stay stage-restricted. Since those now draw from all donors within a stage, the restriction is developmental.”

It designed a test to tell correct integration from over-correction. Your practical only warns you that the difference exists.

Part 4 Clustering

Graph-based clustering

  1. Build a shared nearest neighbour graph — cells connected by how many neighbours they share
  2. Find communities in that graph

A cluster is not a cell type. It is a community in a graph you built, using genes you selected, in a space you chose the dimension of.
